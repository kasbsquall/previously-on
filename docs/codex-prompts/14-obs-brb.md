# Prompt 14

Sent verbatim to Codex in session `01a174cd-3a2a-7f21-a9bf-1289a1e0b57a`.


Ads need an affiliate or partner channel, so the lead trigger cannot be shown live on a normal channel. Every streamer has the same moment without ads: they switch OBS to a "Be right back" scene and viewers miss what happens. Make that a first-class, automatic trigger.

1. **OBS connection.** Read the obs-websocket 5.x protocol docs first (https://github.com/obsproject/obs-websocket/blob/master/docs/generated/protocol.md): Hello, Identify with the SHA-256 authentication, event subscriptions, `CurrentProgramSceneChanged`, `GetSceneList`. Implement a small client on the `ws` dependency we already have (no new dependency unless the docs make it clearly safer). Env: `OBS_WEBSOCKET_URL` (default `ws://127.0.0.1:4455`), `OBS_WEBSOCKET_PASSWORD`, `OBS_BREAK_SCENE`. Never log the password. Reconnect with backoff if OBS closes; the rest of the app keeps working without OBS.
2. **BRB as a break trigger.** When the program scene changes to the break scene, start a break exactly like the panel's "Going on break": build the card at once from the window before the switch, keep it waiting in the panel during the break ("Airs when you leave the BRB scene"), reviewable like the ad-break card. When the program scene changes away from the break scene, end the break: the card airs if approved, or if not vetoed in timed mode; hold mode needs approval. Same 10-second rule if the card is not ready. The stub reads "Back from BRB" with the minutes away. The panel buttons keep working for streamers without OBS.
3. **Panel.** In Connection, an "OBS" row: connected, not configured, or reconnecting. A "Break scene" picker filled from `GetSceneList`, persisted in `.data/` like the other settings (env value is the default).
4. **`npm run check-obs`:** connects, authenticates, prints the OBS version, the scene list and the current program scene, then exits.
5. **Demo and judge page.** `npm run demo` keeps working without OBS. On the judge page add a fourth recorded card, "Streamer back from BRB", recorded the same way (re-run `npm run record-demo`; the key in `.env` is approved), and order the buttons: Ad break ends, Back from BRB, Raid arrives, A viewer types !catchup. Rebuild with `npm run build:web`.
6. **README** (stay under 9,000 characters): the one-liner becomes "Viewers who come back from an ad break or a BRB break, or join mid-stream, get a 15-second recap of what they missed." In the points: it fires on its own when an ad break starts (affiliates and partners) or when the streamer switches to their BRB scene in OBS (any channel), and the streamer reviews the card during the break. Setup line for OBS: enable Tools > WebSocket Server Settings, keep authentication on, put the password in `.env`.
7. Update `SPEC.md`. Tests with a mocked OBS server: auth success and failure, scene change into and out of the break scene, reconnect, picker persistence, no password in logs. Run `npm test` and report. Do not commit.
