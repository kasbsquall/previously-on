# Prompt 11

Sent verbatim to Codex in session `01a174cd-3a2a-7f21-a9bf-1289a1e0b57a`.


A blind review panel scored Previously On lowest on Design ("a recap card on its own isn't exciting to watch") and rewarded entries that use more native Twitch features. This prompt turns the card into a short TV-style "previously on" moment and adds a Twitch clip as a receipt. Keep everything that works today; every new piece must fail soft.

1. **Cold open.** When a card goes on air, play a short broadcast-style title sting on the overlay before the ticket: "PREVIOUSLY ON" and the channel name, about 1.2 s in total, then the ticket enters as it does now. Follow `DESIGN.md` (tokens, Hanken Grotesk, the Boarding Stub look; the sting should read as the same printed-ticket world, not a new style). Animate only transform and opacity. With `prefers-reduced-motion`, skip the sting and show the ticket directly.
2. **Sound.** `public/sfx/` holds two CC0 files I added (see `public/sfx/LICENSE.txt`): `sting.ogg` for the cold open and `stamp.ogg` for the moment the RECAP stamp lands. Play them in the overlay. Keep the volume modest.
3. **Narrator voice.** The overlay reads the card aloud like a TV recap narrator: "Previously on {channel}." then the headline and the bullets. Read the current OpenAI docs first and pick the current text-to-speech model and a voice; if the model accepts style instructions, ask for a warm, slightly dramatic TV-recap narrator. Generate the audio on the server when the card is built, so it is ready when the card is approved; cache it under `.data/audio/` and serve it from a route that only accepts a validated card id (no path traversal). The ticket stays on air at least as long as the voice plus 2 seconds. If there is no key, the call fails or times out, or the browser refuses to play, the card shows silently and the terminal logs one line. No TTS call for vetoed-before-build or dropped cards.
4. **Panel settings.** Two toggles in the panel, persisted in `.data/` like the approval setting: "Narrator voice" and "Sound effects", both on by default. The panel says that card text is sent to OpenAI to make the voice.
5. **Clip receipt.** Read the Twitch docs first (Create Clip, Get Clips, Create Stream Marker, their scopes, whether they work for channels that are not affiliates, and the delay before a clip is ready). When a real ad break begins and when a real raid arrives, create a clip of the moments just before and a stream marker named "Previously On: ad break" or "Previously On: raid". When that card posts to chat, append the clip link ("Watch the moment: <url>") once Get Clips confirms the clip exists; otherwise post without it. Show the clip link in the panel log row. Add the needed scopes to the device flow and make `npm run check-twitch` report whether they were granted. Simulated triggers make no Twitch API calls; the log says the clip was skipped because the trigger was simulated. Any failure (not live, clips disabled, missing scope, rate limit) is logged and the card continues without the link.
6. **Demo.** `npm run demo` shows the cold open, the sounds and the voice when `OPENAI_API_KEY` is set.
7. Update `SPEC.md`, `.env.example` if needed, and the README sections that describe the triggers, settings and privacy (voice text goes to OpenAI; OBS needs the browser source audio enabled to hear the voice). Tests for the toggles, the audio route validation and cache, TTS mocked with its failure paths, clip and marker calls mocked with their failure paths, the simulated-trigger skip, and the scope list. Run `npm test` and report, including what you could not verify. Do not commit.
